1. Выполненные задания
В ходе выполнения задания были реализованы следующие эксперименты:

1.1 Базовый класс Test с "говорящими" конструкторами/деструктором
Создан класс с конструктором по умолчанию, конструктором копирования и деструктором, которые выводят сообщения на консоль.

Добавлено статическое поле nCount, подсчитывающее количество существующих объектов.

1.2 Исследование времени жизни объектов
Глобальный объект — создаётся до main(), уничтожается после main().

Локальный объект — создаётся при входе в блок, уничтожается при выходе.

Динамический объект (new/delete) — живёт до явного удаления.

Динамический массив — требует delete[] для корректного удаления всех элементов.

1.3 Передача объектов по значению
Функция foo(Test t) показала, что при передаче по значению вызывается конструктор копирования, а при выходе из функции — деструктор копии.

1.4 Наследование и агрегация
Класс Child (наследник) — сначала вызывается конструктор базового класса Test, затем конструктор потомка. Деструкторы — в обратном порядке.

Класс Aggregate (агрегат) — сначала создаётся поле m_objTest, затем конструктор агрегата. Разрушение — обратное.

1.5 Шаблон-агрегат AggregateT<T>
Показано, что шаблоны работают с любым типом, сохраняя тот же порядок создания/уничтожения.

2. Ответы на вопросы из задания
a) Какие случаи неявного копирования объектов существуют в C++? (их 2)
Ответ: В C++ существует два основных случая неявного копирования:

Передача параметра по значению — когда объект передаётся в функцию не по ссылке, а по значению.

Возврат объекта из функции по значению — когда функция возвращает объект (не ссылку).

*Экспериментально подтверждено в п.8-9 задания: при вызове foo(Test t) создавалась копия объекта.*

b) В каком порядке создаются составные объекты (потоки или агрегаты в C++)?
Ответ: Порядок создания (инициализации) составных объектов в C++:

Сначала создаются базовые классы (в порядке наследования).

Затем создаются поля-члены (в порядке их объявления в классе).

Последним выполняется тело конструктора самого класса.

Разрушение происходит в строго обратном порядке.

Для Child: сначала Test(), потом Child()

Для Aggregate: сначала Test() (поле), потом Aggregate()

c) Для чего предназначен интерфейс IDisposable в C#?
Ответ: Интерфейс IDisposable в C# предназначен для освобождения неуправляемых ресурсов (файлы, сетевые соединения, подключения к БД и т.п.), которые не собираются сборщиком мусора автоматически. Он содержит метод Dispose(), который вызывается явно или через блок using.

d) Будет ли вызван Dispose по завершению блока using, если на объект, указанный в using имеется еще одна ссылка?
Ответ: Да, будет вызван. Блок using гарантирует вызов Dispose() при выходе из блока независимо от наличия других ссылок на объект. Однако после вызова Dispose() объект считается непригодным для использования, и любые операции с ним (кроме повторного вызова Dispose) вызовут исключение ObjectDisposedException.

e) Как вызвать конструктор предка с параметром в C++?
Ответ: В C++ конструктор базового класса с параметрами вызывается через список инициализации конструктора потомка.

f) Как вызвать конструктор предка с параметром в C#?
Ответ: В C# конструктор базового класса вызывается через ключевое слово base в списке инициализации конструктора потомка.

g) Как вызвать конструктор члена класса с параметром?
Ответ: В C++ конструктор поля-члена с параметрами вызывается через список инициализации конструктора агрегата.

h) Опишите различие в понятии ссылка в смысле C++ и в смысле .Net.
Различие в понятии ссылка в C++ и в .NET (C#):

Суть:
В C++ ссылка — это альтернативное имя переменной (псевдоним).
В .NET ссылка — это указатель на объект в куче (управляемая ссылка).

Null:
В C++ ссылка не может быть null, она всегда должна быть связана с существующим объектом.
В .NET ссылка может быть null, то есть не указывать ни на какой объект.

Переназначение:
В C++ ссылку нельзя перенаправить на другой объект после инициализации.
В .NET ссылку можно перенаправить на другой объект (присвоить новое значение).

Арифметика:
В C++ арифметика ссылок не поддерживается (в отличие от указателей).
В .NET арифметика ссылок также не поддерживается.

Использование:
В C++ ссылки применяются в основном для эффективной передачи параметров в функции (чтобы избежать копирования).
В .NET ссылки являются основой работы с объектами ссылочных типов (class).
